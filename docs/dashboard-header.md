# Dashboard header

The header reserves 52 CSS pixels plus the actual top safe area. Its 44 px controls and 8 px bottom padding share the available width with the connection status. Bottom navigation reserves one fixed 50 px box plus the bottom inset. The riding layout gate measures both reservations and requires at least 12 px below complete content.

A compact notice replaces the brand without adding a row. Fault, Reload and Setup share one counted link to the existing Settings root; it never acknowledges a notice. The measured label changes to icon and exact count when needed, with its full meaning in the accessible name. The full brand loses tracking when necessary rather than being ellipsized.

The header menu calls the existing openSheet() path, whose lazy refresh must run on opening. On a destination page the same control returns to its actual origin, including Cooling. The Faults tab owns the warning badge: duplicating it in the header makes a warning easier to ignore.

The CAN dot is unknown whenever the dashboard connection is not live. A retained can_link value cannot establish current adapter state while messages have stopped. The named system status is authoritative when available; the older signal fallback can establish down from zero, and otherwise stays unknown. The separate connection dot reports dashboard liveness.
